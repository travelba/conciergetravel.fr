## Root cause

### A. "0 hôtels" (51 pages) — zero-entry rankings published

The combinator generated geographic×theme rankings for combos with **no
qualifying hotel** (e.g. `meilleurs-hotels-montagne-saint-tropez`,
`meilleurs-hotels-montagne-bordeaux` — there are no mountain hotels at the
seaside; `meilleurs-5-etoiles-ile-de-france`, etc.). These rows were
**published with 0 entries** and carry a **scaffold `factual_summary`** that
renders verbatim — e.g. `/classement/meilleurs-5-etoiles-bordeaux` shows
"Classement éditorial de **0 hôtels à la montagne**" (the "à la montagne"
default is itself wrong for a 5-étoiles-Bordeaux page → confirms a templated
scaffold summary stored at generation time).

This is the **exact class** the 2026-06-23 `/classements` "0 hôtels" incident
flagged, and matches the documented precedent where "13 zero-inventory slugs
were intentionally unpublished after the matrix re-scan" (AGENTS.md §4bis) —
these 51 are a **regression**: a later bulk run re-published empty combos.

### B. Scaffolding leak (66 pages) — brief/dossier prose leaked live

66 ranking pages render scaffolding meta-commentary in their editorial prose
(the same leak class remediated catalogue-wide on hotel fiches in AGENTS waves
5/11/12). Heavily represented: the `top-<brand>-hotels-monde` chain rankings
(Anantara, Belmond, Capella, Edition, Fairmont, Kempinski, Ritz-Carlton) and
`top-relais-chateaux-<country>` + several geographic ones — i.e. the rankings
were generated by a path that did not run the shared `hasLeak()` write-gate.

## Recommended remediation (needs DB access + PO go-ahead)

Mutating ~120 **published** ranking pages is editorial-content work (not QA
tooling) and is governed by the DataForSEO grounding hard-rule + the content
gates. Proposed forward-only plan:

1. **Unpublish the 51 zero-entry rankings** (`is_published=false`). Cleanest fix
   — an empty ranking has no editorial value and should never be live. Mirror it
   into `combinator.ts` (eligibility gate ≥ 3 hotels) so the next bulk run can't
   re-publish them. Same approach as the prior 13-slug unpublish.
2. **Descaffold the 66 leaking rankings** via the existing tooling
   (`descaffold-sections.ts` / `strip-leak-sentences.ts` analogues for
   `editorial_rankings`), re-grounding via DataForSEO when sections are
   regenerated (hard rule `.cursor/rules/dataforseo-content-grounding.mdc`).
3. **Acceptance**: re-run the crawler on the `rankings` group → expect
   `list-value` + `scaffolding-leak` = 0.
4. **(Separate, lower priority)** the 805 `title > 70` warns — tighten the
   ranking title template (a systemic SEO quality pass, non-blocking).
